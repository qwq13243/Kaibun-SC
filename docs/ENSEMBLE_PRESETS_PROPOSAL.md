# 角色演出预设方案：剧本模型保持原接口，小模型选择细分预设

## 已确认的分工

剧本模型恢复原来的写作与修改接口：正文、日中对白、原有切分、七类 emotion，以及既有的说话人、镜头、旁观人物状态等。七类仍为 calm、happy、shy、surprised、sad、angry、thinking。

不向剧本模型发送原始表情／口型／动作菜单，不要求它返回 expression、face_*、嘴型或 preset_id，也不让它从 35 个风格中选择。本轮已撤回这些扩充，并过滤已有作品演出字段进入写作上下文的情况；原正文和旧七类状态保留。手动微调及已有作品中的原始演出信息继续兼容。

小模型在剧本保存后，接收本幕完整对白、剧本模型已经给出的七类情绪、说话／入镜情况及上一阶段状态，再从对应角色、对应情绪的细分预设中选择。小模型不重写正文，不另做一句话内部的切分或自动变化。

## 一条台词的流转

1. 剧本模型保存一条原有格式台词，例如 emotion=happy，正文和原切分照旧。
2. 程序读取本幕实际人物、实际衣装、已有演出状态、手动锁定和旁观入镜位置。
3. 小模型通读本幕，针对该人物的 happy 候选，判断更适合轻快回应、期待邀请、安心满足、兴奋分享或其他已建库的具体风格。
4. 小模型返回必要的预设变化事件，标明台词 id、人物、预设 id 和简短依据。没有变化的位置延续已选预设，不按每句话轮换。
5. 本地将预设展开为已验证的面部、静止嘴型、说话口型和保持动作，保存为独立制作计划。播放、跳句和导出读取同一计划，不重新请求模型。

预设 id 属于演出制作结果，不属于剧本模型输出。制作计划不能反向混入下一次写作提示，避免又把原始动画控制交给编剧。

## 五种预设的含义

每类先设计约五种偏好明确的预设。差异来自情绪质地与强度、外显程度、交流用途、面部和嘴型基调以及身体幅度，而不是换五个编号。

例如同为开心，可以区分轻快回应、带着期待邀请、放心后的满足、兴奋分享、强烈但收敛的欣喜。这里只是待匹配方向，具体角色必须从真实素材出发，不能给所有角色硬套同一身体表现；情绪强烈也不等于动作必须大。

口型与完整面部表现要协调。普通开心应呈正向微笑基调；闭眼、哭泣等是预设内部的资源选择，不重新加入剧本模型的七类枚举。每套组合分别验证静止嘴型和说话代表帧，不能只凭原始文件名前缀断言嘴型正确。

## 查看具体动作

按角色和情绪查阅[完整演出预设](../config/performance_presets.json)，其中记录了候选的用途、表情、口型、保持姿态和变体，特殊动作单列。原始动作名称可在[姿态与表情目录](../config/stand_catalog.json)中核对。五组是每种情绪的预设结构；遇到停用、合并或当前衣装不支持的预设，演出模型只从实际可用的候选中选。要看实际效果，请用该角色的本机衣装在作品「微调」中预览。

## 原始姿态优先与全部姿态有机会

当前共有 29 套默认衣装、550 个保持姿态，每人 13—25 个；无保持循环的动作不重新纳入。

先按原始类别分配该类已有姿态。某角色有三种害羞保持姿态，就先分别为它们建立害羞组合，再结合真实可用的面部和口型说明各自偏好；剩余名额再从已有标注中确实适配害羞的其他姿态补充。跨类必须有条件，不为凑五个强配。

同时检查每个保持姿态至少进入一个启用、可触发的组合。五个是常规规模，不应成为遗漏姿态的理由：同偏好的等价姿态可以列成预设变体；存在实际表达区别时，允许增加预设。若坚持五个固定单姿态组合，例如叶月八种待机会无法全部分配，这个数量冲突不能靠标注掩盖。

小模型基于语境选择，不按未使用清单逐个遍历。建库验收要列出每个姿态对应的预设及适用条件、原始类别覆盖、未覆盖列表、是否被后续规则永久排除。相似且适用条件相同的组合不编造心理区别；必要的变体选择应一次确定并保存，重播与导出不能重新抽取。

保证的是“每种姿态在合适语境下有可选入口”，不强迫每篇作品用齐；没有出现对应情境时不能为覆盖率强行换动作。

## 延续已有演出规则

- 具体手动设置优先，预设不能覆盖用户已指定的口型／表情／保持动作。
- 非说话角色入镜使用实际可用待机，直接显示保持段，不播放从其他状态恢复到待机的前段；面部仍可反映其自身情绪。
- 旁观期间身体保持，本人发言时才由小模型按对应情绪的候选决定必要变化。
- 相同组合连续出现不重启身体；没有更贴切的变化时保持，不按句数或秒数插入待机，不强制轮换。
- 相似的大姿态连续更换需有明确的表达收益；小幅变化或表达明显不同的大姿态可以在原有切分台词之间使用。
- 七类情绪用于限定候选家族，身体原始文件名只作为来源和建库依据。某个害羞预设可以使用已有标注明确适配害羞的其他原始类别姿态。
- 预设上线后，需要避免旧的“emotion=calm 再强制覆盖成任意 wait”挡掉已选组合。平静待机应落实为所选平静预设／待机组，不能在解析预设后再另猜一遍。

预设减少每次临时拼装面部与身体的兼容判断，不替代必要的连续性和出入镜规则。

## 小模型如何选，以及如何节省 token

小模型读取本幕上下文及原七类情绪，在该情绪下选择偏好最贴合的预设；不重新发明七类情绪，也不把任一动作名机械等同于唯一情绪。明显的情绪／台词矛盾可以标记供检查，不擅自改写剧本模型的情绪或正文。

不逐句请求：保持现有逐幕联合准备，同一请求处理本幕衣装、背景和必要的预设变化。按本幕实际出现的情绪发送候选：若某人本幕仅有 happy 和 shy，通常只需这两类约十条短预设说明，不需要七类全发，更不用把全部角色的组合库发给模型。每类候选内保留全部五种偏好，不固定截取前三名使其他预设永远不可选。

模型只看预设 id、风格、强度、幅度、适用条件及必要禁用条件。原始动画名、详细视觉标注和资源映射保留在本地；输出只含变化事件，不重复回传全部组合数据。配音与演出准备继续并行，完成的场景和制作缓存沿用。

剧本模型输入规模恢复原状，小模型的身体长候选变成短预设说明，因此有望减少演出输入与输出；这仍需要同一作品前后实测，不能凭请求数直接给出节省比例。

## 配音保持原接口

配音继续沿用原有 emotion 及既有服务转换流程。本轮不要求剧本模型增加 voice_emotion，不新增 35 个配音标签，也不因细分预设变化重新生成相同配音。

视觉预设的面部、嘴型和动作由小模型选择及本地映射决定，不能再由配音情绪的备用口型暗中覆盖。这样实现制作与配音的分工，同时不改编剧模型的接口。

## 一次性建库与当前边界

若暂按 29 人、每人约 35 套计算，约 1,015 个组合；静止与说话两种代表状态约需 2,030 张本地预览。初步批次规划仍可按每人一次设计、每人一至两批核验，约 58—87 次基础请求，局部修复另计。实际数量随姿态覆盖和预设可辨别程度调整，金额需依据图片用量及所选接口实测。

本轮已做：回退剧本模型的原始表情／预设输出扩充，保留原有七类、原切分和其他修复，更新本方案。尚未调用 Terra、生成五种预设，或将小模型从旧身体事件改造成新预设选择器。
