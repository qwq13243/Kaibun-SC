# 衣装与演出指南（给用户和 Agent）

## 给 Agent：先确定用户想改什么

- 想给一篇故事换装：使用「新故事」中的单人手选，或打开已有作品的「场景服装」。不要改全局默认。
- 想让以后创作默认使用某套衣装：使用首页「默认衣装选择」，由用户挑选，你负责把导出的设置合并到本机配置。
- 想检查动作与表情：用同一套衣装进入短篇的「微调」和播放器，检查实际动作，不凭衣装名称或静帧判定兼容。
- 先确认现有安装目录、素材目录以及用户想试的角色。已有素材优先；未经同意不要下载全目录、上传图片给模型、覆盖配置，或改动已有作品。

## 1. 接入本机素材

先读 [README 的素材说明](../README.md#立绘与衣装)和[部署指南](DEPLOYMENT.md)。有自备且可使用的素材时，在项目根目录的本机 `.env` 设置 `KAIBUN_ASSET_ROOT` 指向素材根目录（不是 `spine` 或某套衣装的子目录）。保留其他设置，不显示密钥。

```text
<素材根目录的父目录>/
  spine_manifest.json
  <素材根目录>/
    spine/idols/stand/1030010010/
      data.json
      data.atlas
      data.png
```

清单路径使用相对于素材根目录的 `spine/idols/stand/1030010010/`，`idolId` 是 `characters/characters.toml` 对应角色的 `idol_id`；在衣装配置中只写 `stand/1030010010`。编号仅用于展示格式，实际以本机衣装卡片和清单为准。Spine 3.6 运行库不随源码分发；若你有相应使用权，把兼容的 `spine-webgl.js` 放在 `frontend/public/vendor/spine-3.6/`。

没有本机素材时，可让 Agent 按 README 的下载流程先试一位角色的默认衣装（例如真乃）：在 `backend` 运行 `uv run python scripts/fetch_stands.py --character mano`。不要默认加 `--all`。重启 Kaibun 后，先确认角色和缩略图可用；需要时用 `uv run python scripts/doctor.py --running` 检查本机服务、清单及运行库。只选衣装、浏览缩略图不需要调用看图模型。

## 2. 在网页里选择并应用

1. 打开本机 Kaibun 首页的「默认衣装选择」（`/outfit-review`）。选角色、选春／夏／秋／冬或特殊，再点衣装卡片。页面只列本机可用的衣装。
2. 点击「导出 JSON」。浏览器的草稿和导出的 `kaibun-default-outfits.json` **不会直接改掉当前默认衣装**，也不会给旧故事换装。
3. 把导出的文件交给本机 Agent，说明哪些角色和分类要应用。Agent 先备份 `config/seasonal_outfits.json`，确认导出文件的结构为 `version: 1` 与 `default_outfits`，核对每套衣装已安装且属于该角色，再按「角色 → 分类」合并。没选的分类保留原值，别用部分导出覆盖整张默认表。
4. 保存后重启并打开「新故事」试选该季节。单独手选的角色衣装优先。旧作品如需换装，请在「场景服装」手动改；未安装的衣装不会因为存在于默认表就能使用。
5. 更新源码前另存一份自己的衣装 JSON。新版可能更新自带默认表，更新后只合并你自己选过的项目。

## 3. 没有兼容标注的衣装

不必替所有衣装补标注。先让程序复用能识别的预设；如果动作无法预先核对，或提示某行将使用替代动作，按提示跳到对应台词。在本机预览该句和前后各一句；重点看手臂、表情、嘴型和动作衔接。需要时在「微调」里改那一处，不要为换衣重新生成配音。仍无法正常显示时换回已验证的衣装。

## 4. 仓库里可以放什么

衣装选择页作为 Kaibun 的本机页面随源码分发，它依赖本机后端，不是可直接部署到 GitHub Pages 的页面。姿态、表情和预设审查页可另做不带图片的静态参考，公开可分发的筛选界面与自制文字索引；动态预览放在本机，用用户自备的素材渲染。现有审查目录含游戏素材的渲染帧和内部记录，不要整包上传。游戏原始素材、贴图、预览截图、运行库、语音、作品和个人配置不随发行包分发。项目的素材边界见 [LICENSING.md](../LICENSING.md)。
